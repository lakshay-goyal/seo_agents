Critical review · exploration + on-page stages

SEO agents: what works, what's wrong, and how to make exploration accurate and cheap

This review covers every exploration agent, tool, profile and skill in seo_agents, the new on-page stage in src/seo_agents/onpage/, and the output pushed to lakshay-goyal/my-portfolio PR #8. Findings were checked against the client's source and the live site. Accuracy is ranked first, then context size, then model cost.

Five independent audits ran in parallel: orchestration core, tool layer, category agents and skills, on-page stage, and PR #8 output. Claims marked verified were reproduced with a probe script or checked against the live site with curl.

1. Executive summary

The design direction is right: deterministic facts first, an edit location attached to every value, cheap models only for gaps, and a JSON hand-off to a later stage. The implementation has three structural problems that hurt accuracy more than any prompt change could fix:

  1. Pages and served behaviour are under-discovered. On PR #8 the model found 1 of 5 routes. /about, /bookshelf, /blog and /blog/:slug were missed because the SPA adapter only recognises router libraries, and this site routes on window.location.pathname. Robots, sitemap, soft-404, HSTS and trailing-slash were all measured against the apex host that 307-redirects, so they came back null or wrong.
  2. Edit locations are often wrong, and the validator doesn't notice. About 70% of link edit pointers in PR #8 are wrong: nav links point at section titles in App.jsx rather than PageRail.jsx:2-5, and contact links point at unrelated components rather than ContactRail.jsx:7-11. computed/add edits and line:1 placeholders pass grounding, and validation.issue_count still reports 0.
  3. Three or four parallel implementations of the same thing. Route discovery, import resolution, heading/link/media extraction and front-matter parsing each exist 3-5 times (routes.py, adapters.py, inventory.py, react_source.py, page_inventory.py, element_index.py, source_context.py). They disagree. repo_context.pages[0] says / has 0 headings and 0 links, while the page shard says 10 and 19, and nothing says which one wins.

The on-page stage runs end to end at about $0.39/page. Of the 86 proposed changes for /, roughly 22-28 are distinct and applicable. The rest are duplicates, conflicts, false positives or prose advice. Several high-priority changes (canonical, title, OG, JSON-LD, H1) would hurt this site if applied: the Vite SPA serves one index.html for every route, so they would turn into site-wide duplicates.

The single 406 KB repo_context.json (about 101k tokens) should not be an execution input. 34% of it is keyword occurrence lists, 24% comes from README.md being treated as page content, and 5% is empty count:0 signals. A planner summary of about 6k tokens plus per-category shards of 1-3k tokens would hold the same facts. That cuts the per-fix working set from about 108k to under 8k tokens.

Security, fix before the next run on a third-party repo: build_serve.run passes the full environment, including GITHUB_TOKEN (classic PAT, repo scope) and OPENROUTER_API_KEY, into npm install/build of untrusted code (runtime/build_serve.py:203,274). Any postinstall script can exfiltrate them. Details in section 4.

2. Top 12 priorities (accuracy-weighted)

  1. securityScrub the build environment and split containers. Clone and PR steps get the token. Build and serve run credential-less, as non-root, in a fresh per-run container with limits. Kill builds by process group. Stop passing secrets through docker exec -e, where they show up in the host process list.
  2. accuracyDiscover URLs from the rendered site, not only router patterns. Seed the crawl from rendered <a href>, pathname comparisons (location.pathname === '/x'), nav arrays, sitemaps and content folders. Feed gap-worker instances_suggested back into the manifest; today they are dropped.
  3. accuracyResolve the canonical host before measuring served behaviour. Follow apex→www and http→https first, then probe robots, sitemap, soft-404, headers and trailing slash on the final host. Remove the hard-coded /about trailing-slash probe (site_model.py:424).
  4. accuracyMake the grounding validator real. Reject line:1 and template-call-site fallbacks for computed. Derive edit_kind in code from the chosen candidate instead of trusting the LLM (gap_workers.py:302). Add JSON Schema validation, since docs/site-model.md exists only as prose. Add a sampled edit-replay check: apply a sentinel edit, re-render, and confirm the value changed.
  5. accuracyCollapse to one IR. Keep element_index + adapters + source_lens. Delete or demote inventory.py, react_source.py, page_inventory.py, source_context extraction, the 7 dead agent wrappers, and the legacy LLM extractor path. Compute repo_context signals from the IR.
  6. accuracyMark scope on every edit location: shell (index.html / root layout, affects all routes), layout, template(n) (.map() over data, affects N instances), data (JSON pointer, safe per-instance), or literal. Add shared_by: [routes]. Without this, the on-page stage can't tell a safe edit from a site-wide one.
  7. accuracyFix the verified extractor bugs: framework misdetection (config.json→hugo, urls.py→django), canonical_values reading neighbouring lines, html lang={expr}→"params", noindex matching nofollow, social-profile false positives, redirects/redirect_rules key mismatch, the Svelte {#if} comment bug, and the static-site crash in react_source.discover_app.
  8. contextShard the output. Use manifest, summary, routes, pages, images, links, metadata, structured_data, performance and evidence files. Stable content-hashed IDs, compact JSON, no empty containers, README/docs excluded from content. Stop committing the full JSON to the client repo.
  9. on-pageAdd a deterministic scope gate and dedup pass to the on-page stage. One atomic op per change, keyed by dedup_key. Block head changes on a shared SPA shell behind depends_on: prerender. Separate changes[] from advice[]/client_inputs[]. Fix the HIGH-priority key bug (checks.py:30) and the duplicate IDs.
  10. costTier models by task and turn on caching. Honour the skill tier: frontmatter. Use structured outputs (response_format JSON schema). Add cache_control on shared principles. Separate transport retries from validation retries. Stop forcing reasoning_effort=none on the mid tier.
  11. frameworkAdd attribution via build instrumentation. A Babel/SWC/Vite plugin stamps data-src="file:line:col" on rendered nodes (React jsx-source, Vue __file, Svelte inspector, Astro dev toolbar). String-match attribution stays as the fallback.
  12. evalsBuild a real eval set. About 20 pinned OSS sites across stacks, plus this portfolio, scored on URL recall, field accuracy and edit-location accuracy in rendered mode. Track cost and latency per commit. The current 13 toy fixtures are scored source-only against self-authored targets.

3. How the system works today

A run boots a long-lived container and clones the repo. It then runs three stacked output systems over one snapshot, and optionally the on-page stage.

  • Deterministic vs LLM: everything in the site model is code except the gap workers (single-shot, tool-less, small model with escalation to mid) and the learned route adapter. The legacy path is entirely LLM-written code.
  • "Sub-agents" in the site model are stateless single completions over a task packet. That is the right shape. The orchestrator should stay code, not an LLM supervisor.
  • Models: small = OPENROUTER_SMALL_MODEL, falling back to DeepSeek Flash. mid = hard-coded anthropic/claude-sonnet-5.5 (tools/llm.py:30). There is no Haiku-class tier between them.
  • Default run is the weakest lens. Without --site-url or --render, a Vite SPA is analysed source-only. The source lens doesn't evaluate conditionals or mapped lists (source_lens.py:563).

5. Orchestration & pipeline

Correctness defects

  • Grounding is bypassed by the most common fallbacks. computed/cms/add edits only need the file to exist (site_model.py:121-122). Attribution fallbacks emit {kind: computed, line: 1} (attribution.py:199,332), and add_location emits line: 1 (source_lens.py:819). Any via/i18n_key disables the value check (site_model.py:136). The "schema" check listed at site_model.py:342 doesn't exist.
  • The LLM's edit_kind overrides the candidate's real kind (gap_workers.py:302). explain_computed with none changes the kind but keeps the old file and line.
  • Route adapter, the most consequential LLM task, gets one attempt (gap_workers.py:176, tier: mid skips the ladder).
  • instances_suggested is never used (gap_workers.py:333). There is no loop edge from gap results back to url_manifest.
  • Build artifacts are indexed as source. SKIP_DIRS misses out, _site, public (Hugo output) and docs. Stale committed dist/ is served as ground truth by default (SEO_MEASURE_PREBUILT, build_serve.py:34,245).
  • Snapshot starvation. Assets count toward max_files=2000, and the sorted walk visits public/ before src/. An image-heavy repo can end up capturing no source.
  • Hidden files are excluded, so the .env.production host hints in url_manifest.py:59-60 never fire.
  • SEO_MEASURE_WORKERS can't lower concurrency: max(workers, SEO_GAP_CONCURRENCY) (site_graph.py:373). Each URL also launches a fresh Chromium.
  • Lighthouse is serial (12 pages × 2 form factors × 3 runs × 180 s) inside attribute. One failed run discards the others (lighthouse.py:86). On PR #8 performance status:"failed", yet the ledger says measured.
  • Repeated content blocks lose their edit locations because matching uses a dict keyed by normalised text (attribution.py:341).
  • A legacy-agent failure kills the PR. ExplorationIncomplete is uncaught (pipeline.py:139), even though the site model is already on disk.
  • Settings and config gaps: FORWARDED_ENV omits SEO_MEASURE_PREBUILT, SEO_MAX_CRAWL_DEPTH, the cache vars and all LANGSMITH_*. A global OPENROUTER_REASONING_EFFORT=none disables Sonnet reasoning on escalation. An invalid URL exits 0. The PR branch is fixed and force-pushed, so every run overwrites the previous one.

Duplication & dead code

  • Three parsers over the same source: SourceIndex/page_inventory (→ repo_context), element_index/source_lens (→ site model), and inventory.py + LLM extractors (legacy). build_element_index runs twice (pipeline.py:138), and the manifest is rebuilt three times (site_graph.py:140,230,248).
  • Dead code: gap_workers.run_gap_workers (tests only), render.close_browsers (stub), the seven agents/*.py wrappers around extract_category, and json_analysis.py. benchmark_exploration.py benchmarks legacy static mode, not the site model.

Cost leaks

  • Transport and auth errors are caught as "invalid answer" and retried through the ladder (gap_workers.py:195). Stacked on max_retries=2, that is up to 9 HTTP calls per task, and a bad key burns about 3×N calls before anything surfaces.
  • The legacy path serialises the whole snapshot plus an index of up to 24 MB to a subprocess per test_script, and runs accepted scripts twice. The design doc records about 354k input tokens for one content agent.
  • Cost accounting assumes cache reads cost 10% for every provider and ignores cache writes. USAGE is process-global and never reset.

6. Tool layer & framework support

LLM tool-calling surface

Only tools/agent_retrieval.py:62 repository_tools() is exposed to models, and only in the legacy path. It builds 17-19 tools across two overlapping surfaces: read/read_source/read_sources, grep/search_source/search_sources, and query_index/query_context. Problems:

  • Schemas come from type hints plus a one-line docstring. No parameter descriptions, and enums such as query_index(kind=…) are free strings. Small models pay for this with invalid calls.
  • read silently truncates lines over 2000 chars (:277). query_index(page=…) with no match returns empty with no error (:381). find_definition's break exits only the inner loop.
  • grep collects every match before paginating, and page_records re-serialises the growing list each row (quadratic).
  • No history trimming. The worst case resends about 60 × 16 KB per round.

Recommendation: retire "LLM writes an extractor script". The model should choose among deterministic candidates, as gap workers already do. Where a tool-using worker is needed (computed values), give it about 5 tools with documented params, scope them to one page's composition bundle, and cap calls at 3.

Route discovery: concrete failures

  • Pathname-switch SPAs (PR #8): no router library, so they fall back to spa-single-entry (adapters.py:483,642).
  • Next.js: intercepting route app/(.)photo/[id] becomes URL /(.)photo/[id]. [locale] has no locale semantics. App-router i18n (middleware, next-intl) isn't covered.
  • Remix v1: nested app/routes/blog/$slug.tsx is dropped (the regex excludes /).
  • React Router: paths from constants (path: P.ABOUT) are silently dropped with no gap recorded. Separately, parse_object_routes treats any {path:'…'} (for example { path: '/api/v1' }) as a route.
  • static_params misses posts.map(p => ({slug: p.slug})), and any literal slug: 'x' in the file becomes a page verified.
  • Other stacks: Gatsby createPage breaks on a nested context:{}. Front matter is single-line only, with no Hugo TOML +++. Express routes count only with res.render within 400 chars. Laravel reads only routes/web.php and misses groups and resources. Rails ignores nesting.
  • Fixture coverage: 13 tiny fixtures (111 files total). No fixtures for Remix, Gatsby, Angular, 11ty, Docusaurus, VitePress, Qwik, Solid, Rails, Flask, Express, Razor, Ghost, Drupal or Magento, despite the README claiming them.

Source attribution (element_index.py)

  • No value spans. Attributes and text have no start/end col, so the editor has to re-search the literal, which is ambiguous when alt and title share text.
  • Text split by children becomes a non-contiguous "literal": <p>Some <b>bold</b> text</p> gives "Some text", so find-replace fails verified.
  • Element IDs are sha1(file:line:col:tag), so they're invalidated by any line insert above.
  • No data flow: same-file constants, Astro frontmatter constants, Vue :title and parent→child props are not linked. Template literals keep only static fragments.
  • i18n: namespaces aren't resolved (useTranslations('Hero') + t('title') records title). \b_\( and t( match any such function.
  • Shared components aren't flagged. Editing Hero.tsx silently changes every page.

Runtime

  • Next.js SSR (no output:'export') likely can't be served. Preview passes --host, which next start doesn't accept (it uses -H). Remix and Nuxt read PORT. wait_for treats a 500 as "up", and preview output goes to DEVNULL. (CLI flag behaviour from docs, not executed.)
  • Package managers: Yarn 2+ needs --immutable, not --frozen-lockfile. packageManager/corepack and .nvmrc/engines are ignored. Install runs in the package dir, not the workspace root. The build timeout doesn't kill grandchildren.
  • Lighthouse: static files are served by Python's ThreadingHTTPServer (no compression or HTTP/2), so lab numbers aren't production-like. inp_ms is always empty in navigation mode. CrUX field data is fetched only when the Lighthouse CLI is absent.
  • Link checks: HEAD 403/404 from WAFs and CDNs is marked broken. GET is retried only on 405/501. The external sample is the first 50 alphabetically.
  • Crash: react_source.discover_app raises Unresolved React mount entry for any static index.html with <script src>, and for Vue/Svelte Vite apps verified.
  • Comment detection: Svelte {#if} and a string 'src/**/*.js' open a "comment" that wipes up to 4000 chars of signals (skill_runner.py:189) verified.

7. Category agents (per agent)

Important framing. The 14 modules called "agents" in pipeline.explore_codebase are deterministic regex runners over profile JSON. There is no model. skills/*/SKILL.md under repo_analysis/skills/ are human docs, not runtime prompts (skill_runner.py:8). The real prompts are in agents/llm/skills/ and agents/gap/skills/ (section 8). Seven agent files (content_arrangement, eeat_trust_signals, internal_links, media_alt_text, metadata_social_cards, page_structure, url_information_architecture) are dead: nothing imports them.

Cross-cutting problems

  1. Repo-wide booleans instead of per-page facts. A gap fires only if a signal matches nowhere in the repo. One canonical on 1 page out of 400 means "no gap". An editor needs {route → value | absent}.
  2. Records give the location but not the value. Most signals have no value_group (canonical, noindex, hreflang, viewport, font-display).
  3. The same regex runs 3-4 times: "@type" in structured-data, brand, local and AI readiness. document.title= in two profiles. Feeds, OG and responsive images are each duplicated.
  4. Path-based page signals aren't joined to routes. "about-page" matched components/team/Avatar.tsx, and "contact page" matched stores/cart.ts verified.
  5. precision labels are uncalibrated, and caps (25 per file, 150 per signal) silently drop editable values.
  6. Site model ignores agent output. It reads redirects, but the agent emits redirect_rules. rendering_strategy isn't in the consumed list (site_model.py:443-448), so redirect rules and rendering modes never reach the site model.
sitemap_robots

Extracts: static robots.txt groups, <loc> from static sitemaps (cap 500), generator leads, a noindex signal.

Misses: generated robots/sitemap (Next app/robots.ts, sitemap.ts, Nuxt/Gatsby plugins, Hugo/Jekyll templates; a Hugo template parses as parse_error), .xml.gz, sitemap-index children, lastmod, hreflang and image entries.

Wrong: noindex regex includes \bnofollow\b and index:false, so rel="nofollow" and express.static({index:false}) are reported as noindex verified. No route mapping.

Fix: split meta-robots, X-Robots-Tag and metadata-robots, each with a captured value per route. Cross-check Disallow ∩ routes ∩ sitemap ∩ noindex.

canonicals_redirects

Bug: canonical_values runs href= over ±3 context lines (canonicals_redirects.py:48-50) and returned /favicon.ico and a tweet-intent URL as canonicals verified.

Misses: netlify.toml redirects (matched but never parsed), Nuxt routeRules (claimed in SKILL.md), Astro object redirects, Gatsby createRedirect, Hugo aliases, Jekyll redirect_from, nginx conf.d/*. SPA catch-alls (path="*", '**', Nuxt error.vue) aren't recognised as 404 handling.

Wrong: Vercel rewrites are listed as redirects (PR #8 classifies /(.*)→/index.html as redirect-config). A missing permanent should default to 308, but None is returned. RewriteRule without [R] is not a redirect. .Permalink isn't a canonical.

Fix: a per-host parser registry emitting {from,to,status,kind:redirect|rewrite}, chain and loop resolution, and soft-404 risk from catch-alls.

hreflang_i18n

Bug: lang={params.locale} gives value "params" verified. The regex is case-sensitive, so Next <Html lang> in _document is missed and produces a false no-html-lang gap.

Misses: Nuxt htmlAttrs, Gatsby setHtmlAttributes, SvelteKit [[lang]], Remix ($lang), Hugo content/<lang> and index.fr.md, Nuxt prefix strategy, auto-hreflang from useLocaleHead/next-intl/@astrojs/sitemap.

Fix: read {locales, default, strategy} from framework config, mark expressions as value_origin: expression, ignore case.

structured_data

Misses the dominant JS pattern dangerouslySetInnerHTML={{__html: JSON.stringify(obj)}} verified, plus next-seo components, Nuxt useSchemaOrg and Liquid filters. A self-closing script tag followed by a later </script> swallows everything between. @type arrays are missed. Nested types are counted as top-level.

Fix: resolve the object passed to JSON.stringify via tree-sitter, emit {top_level_type, properties, file, route}, validate required props for about 6 key types, and make this the single @type source for brand, local and FAQ.

rendering_strategy

Modes don't cascade from config or root layout (SvelteKit root prerender, Next output:'export', Nuxt ssr:false). Nuxt ssr:false is not classified CSR. Path regexes are anchored at the repo root, so monorepos are missed. Auto-static Next pages have no mode. Angular <app-root> and <div id="app" …> shells are missed.

Fix: per-framework resolver with config → layout → page precedence, emitting route → {mode, source_chain}.

client_diagnostics (react_diagnostics.py) and state_management

Keep 4 SEO-relevant signals: hash-router, JS-only navigation, runtime-head, effect-fetch. Add <a> without href, href="#" and javascript:. Fold them into rendering/links per route. Drop the hydration and security signals.

state_management: almost no SEO value. content_prefetched_on_server is wrong for Next App Router and Nuxt useFetch (which runs server-side). Its own execution_hint contradicts its classification. Delete it and record per-route data source in rendering_strategy instead.

performance_assets / page_latency

legacy_format_assets lists every png/jpg in the repo, uncapped and unreferenced (false positive when next/image or astro:assets converts them). preconnect also matches preload. Third-party bare words match prose. SKILL.md promises missing-dimensions and font-preconnect pairing that the profile doesn't do.

Missing: per-image dimensions, format and lazy-on-LCP, font-display per face, render-blocking head CSS, per-page CWV.

page_latency: a serial HTTP baseline with no CWV, run only in the legacy graph. Rename it or merge it into served probes.

https_security_headers

Counts <meta http-equiv> HSTS/XFO, which browsers ignore. insecure-url flags "@context":"http://schema.org" verified. Gaps fire on Vercel/Netlify/Cloudflare, which add HSTS automatically. On PR #8 the live www sends HSTS, but the JSON reports no-hsts.

For SEO only HTTPS redirect, HSTS and mixed content matter. Move CSP, XFO and Permissions-Policy to an optional profile.

brand_entity_signals / local_business_presence

Brand: social_profiles includes github.com/…/blob/main/README.md and twitter.com/intent/tweet, which are then reported as "missing from sameAs" verified. same-as needs block:true, or arrays longer than 3 lines get truncated.

Local: stores? matches Redux/Pinia store dirs. The "telephone": alternative captures the key, not the value. JSON-LD email is never captured. For non-local sites this is noise; gate it on local-schema/PostalAddress.

shareability_link_assets / ai_search_readiness / mobile_parity / code_exploration

Shareability: the og-image-generator path regex sits in a content signal, so the Next opengraph-image.png convention never matches. The twitter:{card} regex only matches when card is the first key. No OG image validity checks (absolute URL, existence, 1200×630, size).

AI readiness: semantic-landmark and list-table record every <main>/<ul> (tests even assert truncation at 25). Replace them with per-page counts. ai-crawler-rule counts bot-detection UA lists and doesn't distinguish allow from disallow; derive it from parsed robots groups.

Mobile: no-viewport is a false positive on Next/Nuxt/SvelteKit/Gatsby, which inject a default viewport. media-queries emits up to 150 CSS records; use a count. There is no favicon signal anywhere.

code_exploration: tsconfig/babel/postcss/tailwind add nothing for SEO. It misses Hugo config/_default/, react-router.config.ts and wrangler.toml. Hosting files (vercel.json, netlify.toml, _headers) should be a parsed deployment_config.

Legacy LLM extractors (urls, page_structure, internal_links, media, metadata, content, eeat)

These are the only real tool-using agents, but they're scoped per category over the whole repo, which is the wrong axis. Context grows with repo size. Asking a cheap model to write a 30 KB+ program in a restricted Python dialect (no try/except, lambda or imports) is a code-generation task. The design history shows truncated plans, missing ExtractionPlan and exhausted discovery budgets. pipeline.py:103 says the site model already covers their data. Retire them, or keep them only as an offline tool for authoring adapters.

8. Skills & prompts

Exploration gap skills (agents/gap/skills/*), the strongest prompts

Answers are constrained to IDs and enums, there's an untrusted-data clause, family-filtered few-shot examples, and a short "Done when". Weak spots:

  • No structured output. JSON is pulled out by a brace scan (gap_workers.py:57-63). Use response_format with a JSON schema; that removes a whole failure class for cheap models.
  • attribute-value: rule 4 ("data wins only when the template line shows the key") can't be applied from one-line snippets. The model never sees the call-site chain. Don't ask for edit_kind; code knows it.
  • explain-computed: ±6 lines and no access to imported helpers, so the model guesses. The Next example labels a local array literal, which contradicts the json/computed semantics.
  • topic-intent: "realistic searches" invites invented queries with no grounding data. The skill says 2-6 words but the validator allows 1-8. Voting uses exact JSON equality, so "agreement" mostly measures the intent enum. Output lands in keywords as if it were fact.
  • eeat-classify: asks for expertise_evidence, but the harvester never produces that candidate type. Harvest regexes are English-only.
  • route-adapter: sees paths only, no file heads, so it can't tell a page from a partial.

Legacy extractor skills (agents/llm/skills/*, contract-common.md)

  • Compact (180-290 words) with schema, rules and one example. But they have no negative examples (expression values, layout duplication), which is where cheap models drift.
  • internal_links: no external kind, so absolute same-origin links become absolute-unclassified. No JS-only or href="#" field. rel isn't parsed.
  • media: no alt_status: missing|empty|literal|expression, format, decoding or LCP flag.
  • metadata: a loose union record shape. Ignores generator tags (jekyll-seo-tag, Hugo internal templates, Docusaurus themeConfig, Nuxt app.head) and metadataBase.

Trade-off, honestly: one file is atomic and simple to fetch. 12. Target architecture: code orchestrator + cheap workers + verifier

  • Keep the orchestrator as code (LangGraph map-reduce). An LLM supervisor would add cost and nondeterminism for no accuracy gain. Sub-agents are typed, stateless workers.
  • Rendered DOM is ground truth. Source-only becomes an explicit degraded mode with a banner in manifest.json.
  • Fan out per template, not per URL. Attribute one instance deeply and project to siblings by element path. LLM calls then scale with template count, not page count.
  • Add a loop edge from gap results (instances, learned adapters) back to URL discovery.
  • Make it checkpointed: SQLite checkpointer, serialisable state, servers outside state. Today a Lighthouse crash after 30 minutes loses everything except repo_context.json.

13. Prompt, context & harness engineering

Prompt engineering

  • Structured outputs everywhere (response_format JSON schema or a tool-call schema), not brace scanning.
  • Closed-set answers: the model picks candidate IDs and code derives kind, file and line.
  • One positive and one negative few-shot per skill, family-filtered by framework.
  • Remove contradictions between skill text and validators. Generate the numeric limits in prompts from the validator constants.
  • Per-skill principle subsets instead of all of _principles.md.
  • Assign facts to slots before writing copy (prevents the 6× repetition).
  • Honest "unknown" options on every enum, with a penalty-free path.

Context engineering

  • Unit of context = one page's composition bundle (source_lens.composition_for), not the repo.
  • Packets carry the call-site chain, DOM path and neighbouring served text, which the gap workers lack today.
  • On-page packets carry framework, head scope, template multiplicity, pointer confidence and existing aria attributes.
  • Planner reads ≤6k tokens of summary. Workers read one shard. Evidence is lazy.
  • Prompt caching: cache_control on the static system block (OpenRouter → Anthropic).
  • History compaction for any tool-using worker, with hard tool-call caps.

Harness engineering

  • JSON Schema validation on every output file. Referential integrity across shards.
  • Grounding rejects placeholders. A sampled edit-replay check proves pointers are correct.
  • Transport retries (backoff) separate from validation retries (repair prompt). Fail fast on auth.
  • Deterministic: T=0 except prose. Cache keyed by packet + code version.
  • Observability: enable and forward LangSmith, per-node timings and cost in manifest.json.
  • Checkpointing and resume. Per-node budgets that degrade gracefully.

Accuracy guardrails

  • Every fact carries method (rendered / raw / source) and verify status.
  • Coverage ledger per field, not per page, and must reflect failures (performance on PR #8).
  • Cross-output contradiction check (brand agent vs page model edit lines).
  • Self-consistency votes only on enum fields, with agreement measured.
  • Escalate to mid with reasoning on two validation failures, never on the first.

15. Framework-agnostic strategy

  1. Crawl the built site, whatever the framework. Rendered URLs, DOM, head and links are framework-neutral. Route guessing becomes a seed, not the source of truth.
  2. Attribute through instrumentation. Inject data-src="file:line:col" at build time: Babel transform-react-jsx-source or @react-dev-inspector/babel-plugin, Vue __file, svelte-inspector, Astro dev toolbar metadata. Fall back to string-match attribution only when there is no map.
  3. A single adapter interface with one fixture repo each: 
    class Adapter:
    detect(snapshot) -> score            # dependency OR framework config required
    routes(snapshot) -> [Route(url, template, params, i18n)]
    layouts(template) -> [file]           # for head_scope / shared_by

    head_recipe(op) -> Recipe             # where a title/canonical/JSON-LD change goes
    build_plan() -> BuildPlan(install, build, serve, env, port_flag)
  4. Run every adapter above threshold, per package root (monorepos).
  5. Data flow in the tree-sitter pass: same-file constants, prop flow from call site to component, namespaced i18n, and generateStaticParams/getStaticPaths reading imported arrays or content dirs.
  6. Value spans (start/end line and col) for every attribute, text node and data scalar. Content-anchored IDs.
  7. Per-framework runtime recipes: next start -p, PORT= for Remix/Nuxt, vite preview --port, yarn berry --immutable, respect packageManager and .nvmrc, install at the workspace root, and readiness = 2xx on a known route.
  8. Hosting is a first-class fact: Vercel, Netlify, Cloudflare, S3 or nginx, detected from config and response headers. Many fixes (redirect status, soft-404, headers) live there, not in code.
